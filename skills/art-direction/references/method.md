# Art Direction v1 生产规范方法（兼容模式）

本方法用于用户已经锁定视觉方向并明确要求完整 Art Bible，或维护现有 `art-direction.yaml`。默认的视觉选型流程改用 [decision-method.md](decision-method.md)。v1 中的五维评分是暴露生产取舍的启发式记录，不是玩家偏好证据，也不能证明美观。

## 1. 三层分离

所有内容按三层记录，避免把个人偏好伪装成原作事实：

1. **Observation / 观察**：材料中能定位的色彩、明度、光线、构图、形状、材质、镜头、动作或文字现象。
2. **Translation / 转译**：该现象在叙事中承担什么功能，进入游戏时保留、抽象还是替换。
3. **Decision / 决策**：为目标平台、玩法和产能选择的具体视觉规则。

例如，“雨夜里人物被暖色逆光勾边”是观察；“暖光代表自由短暂穿透压抑环境”是功能解释；“平时只用低饱和土灰色，在转机/出口使用金色轮廓光”才是游戏规则。

## 2. 材料与证据

优先级通常为：用户锁定约束 > 实际游戏交互和平台限制 > 可定位的一手原作材料 > 用户提供的二手说明 > 未核验推断。

- 图片和视频帧使用文件名、镜头号或时间码定位。
- 剧本、字幕和小说使用页码、段落、章节或时间码定位。
- 现有游戏工程使用相对路径、组件名、画布尺寸和代表性截图定位。
- 只有故事梗概时，视觉结论标为 `unverified`，审批状态保持 `provisional`。

观察要覆盖全片/全章的重复规律，也要记录高潮、转折和结局的例外。不要用一张著名海报代表整部作品。

## 3. 约束先于风格词

先建立目标矩阵：

- **平台**：屏幕尺寸、横竖屏、输入方式、性能、压缩和加载限制。
- **玩法**：镜头距离、移动速度、交互目标、危险/友军区分、文字量和 HUD 密度。
- **产能**：团队人数、工具、资产数量、动画帧数、迭代周期和可维护性。
- **无障碍**：小屏文字、色觉区分、闪烁、运动敏感和对比度。

约束不是最后补的 QA，而是决定轮廓粗细、细节预算、调色板数量和动画方案的输入。

## 4. Style territories

只有方向未锁定时才提出三个 territory。三者必须在生产制度或视觉语法上有真实差异，而不是同一方向换三个形容词。

可用的差异轴包括：

- 严格像素 vs 混合像素/插画关键帧；
- 写实比例 vs Q 版轮廓；
- 固定俯视 vs 侧视舞台/电影式分镜；
- 受限调色板 vs 场景分区调色板；
- 粗颗粒材质 vs 平涂图形；
- 克制低动态 vs 戏剧化光影与特效。

为保持 v1 数据兼容，五项启发式评分仍为 1–5：

- `source_fidelity`：是否保留原作情绪与叙事功能；
- `gameplay_readability`：目标、角色、空间和反馈是否清楚；
- `production_feasibility`：在当前产能下能否稳定扩产；
- `distinctiveness`：是否形成项目自己的辨识度；
- `system_coherence`：环境、角色、UI、剧情帧能否属于同一世界。

评分相同不意味着效果相同。选型理由必须指出关键取舍和风险。不要把总分称为玩家验证或客观美感结论。

## 5. 视觉内核

视觉内核由以下部分组成：

- **一句方向**：包含情绪、表现制度和最重要的视觉反差。
- **情绪契约**：玩家大部分时间应该感到什么，什么时候允许改变。
- **3–5 个支柱**：每个支柱同时写规则与可验证证据。
- **2–5 个反支柱**：明确哪些看似好看但会破坏本项目。
- **身份 token**：5–12 个跨资产复用的颜色、材质、轮廓、构图或动效词。

“复古、电影感、像素风”不是合格支柱；“场景保持低饱和土灰，只有希望/出口使用暖金边缘光”才是。

## 6. 像素制度

选择一种制度并贯穿资产生产：

- `strict_pixel`：所有可见边缘遵守固定像素网格；最近邻采样；显示优先整数倍；不使用半像素、模糊和任意缩放。
- `hybrid_pixel`：可玩资产遵守像素网格，剧情帧或背景允许高细节栅格；共享调色、边缘锐度、颗粒和光线逻辑；必须列出例外。
- `pixel_influenced`：使用块面、有限色带和硬边，但不承诺逐像素网格；不要在交付中宣称严格像素。
- `non_pixel_2d`：明确采用其他 2D 制度，同样需要原生规格、采样和缩放规则。

混合制度不是降低标准，而是把表现精度按功能分层。剧情帧可以保留电影构图，可玩环境必须优先空间可读性。

## 7. 资产族而非单张图

资产族按叙事与交互功能分，不按文件扩展名分。常见资产族：

- 可玩环境/地图；
- 玩家与 NPC；
- 道具和交互物；
- 对话框、HUD 和菜单；
- 剧情关键帧/漫画镜头；
- 小游戏和谜题界面；
- 粒子、天气和转场。

每个资产族都要回答：原生规格、镜头/投影、缩放、调色板共享方式、轮廓、光线、细节密度、动作节奏、可读性测试、应该做和避免做什么。

## 8. Pilot set

最小 pilot set 的目标是尽早暴露系统冲突。推荐同时测试：

1. 一个典型可玩环境，包含可交互物和碰撞边界；
2. 一个主角与一个 NPC，在实际显示尺寸下并排；
3. 一套 HUD/对话/按钮覆盖在最复杂背景上；
4. 一个情绪高潮剧情帧；
5. 一个场景特有变体，如雨、火、雾或小游戏。

每个测试写“假设—交付物—通过标准”。若同一角色在空白背景上很好看，却无法在场景中辨认，方向仍未通过。

## 9. 提示词胶囊

提示词胶囊给下游图像生成或美术人员复用：

- `style_anchor`：一句不依赖专有作品名/艺术家名的视觉描述；
- `positive_tokens`：结构、明度、材质、轮廓、镜头、色彩和采样规则；
- `negative_tokens`：最容易漂移的禁区；
- `composition_template`：主体、镜头、留白、交互区域和 UI 安全区；
- `asset_specific_notes`：不同资产族的例外。

提示词不能替代 YAML 中的可验证规则。

## 10. 通过标准

生产规范可以标记 `approved`，至少应满足：

- 代表性材料覆盖可信，关键观察可定位；
- 选型明确，重大假设没有伪装成已证实事实；
- 3–5 个支柱能在至少两个资产族中被验证；
- 调色板、明度和轮廓在缩略图/实际设备尺寸下可读；
- UI 与世界共享视觉语言，同时保留操作优先级；
- 关键 pilot 跨资产一致，技术规则可由目标渲染管线实现；
- 已列出版权、产能和风格漂移风险。

`approved` 只表示生产规范获批；目标玩家支持必须由独立的 `visual-decision.yaml` 和 `player-analysis.json` 证明。
