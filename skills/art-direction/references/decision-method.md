# 证据驱动的视觉方向决策方法

本方法服务于缺少专职美术总监的独立创作者。它回答的是“哪套整体视觉假设最值得投入生产”，而不是“模型认为哪张图最好看”。

## 1. 可证伪的产品承诺

一次成功运行必须留下五类可以审阅的事实：

1. 三套候选解决同一个叙事与玩法问题；
2. 每套候选都有真实可见的跨资产综合样板；
3. 每项制作质量门槛都有检查方法和画面证据；
4. 玩家结论来自可复算的匿名原始答卷；
5. 创作者是否接受玩家建议被单独记录。

不把模型自评、风格词数量、文档长度、生成图片数量或加权总分当作成功指标。

## 2. 决策简报

开始候选探索前必须锁定：

- 目标玩家：过去行为、偏好类型、平台习惯，而不是抽象的“年轻人”；
- 目标平台、原生分辨率、画幅和镜头；
- 五秒内必须读出的角色、路径、交互物和反馈；
- 团队人数、周期、工具、资产规模和允许的表现制度；
- 创作者明确喜欢的视觉特征与不可接受的红线；
- 原作的情绪、权力/人物关系和叙事功能。

原作功能写成可以被样板反证的句子。例如“暖光只在回应或出口出现”可以检查；“保留电影感”不能检查。

## 3. 同题 benchmark

三套候选共用一份 benchmark：

- 左侧或主要区域：代表性玩法场景，包含主角、出口和交互物；
- 角色区域：原生游戏显示尺寸的主角/NPC，验证轮廓与身份；
- UI 区域：HUD、按钮或对话覆盖在复杂背景上；
- 叙事区域：同一个关键情绪瞬间。

固定角色、空间、目标、镜头、面板比例、文字量、原生尺寸和生成尝试上限。候选差异只能来自像素制度、形状、调色、光线、材质、UI 和动作语言。

每套第一张样板算一次尝试。只有缺面板、内容错误、明显伪影、错误尺寸/采样等硬失败，才允许一次定向重试。不得因为创作者“不够喜欢”而给某套更多生成机会。

## 4. 制作质量硬门槛

每个候选分别覆盖五类，结果只有 `pass`、`fail`、`pending`：

| 类别 | 回答的问题 | 合格证据示例 |
| --- | --- | --- |
| `source_function` | 是否保留原作必须保留的叙事功能 | 标出压迫框架、希望色或人物关系在四面板中的位置 |
| `craft` | 构图层级、色彩关系和跨资产一致性是否存在明显缺陷 | 原生尺寸与放大图检查，指出主次层级、轮廓和共享 token |
| `readability` | 主角、路径、出口、交互物和 UI 是否可辨 | 五秒预检与缩略图证据，不用主观形容词 |
| `technical` | 尺寸、采样、透明、对比度和平台约束是否成立 | 实际文件尺寸、缩放方式、UI 对比检查 |
| `production` | 团队能否稳定扩产，而非只做出一张样板 | 资产复杂度、动画帧、调色和模板复用说明 |

这一步是缺陷筛选，不负责判断玩家是否喜欢。禁止汇总成“美感总分”。初次进入玩家测试时三套候选必须全部通过；分析阶段至少保留两个合格候选才有比较意义。

## 5. 玩家盲测

测试页使用匿名顺序“方案 1/2/3”，每位参与者的顺序随机。参与者完成：

- 目标玩家筛选和注意力检查；
- 每套样板限时观看后的三项可读性题；
- 每套 1–7 分视觉吸引力、叙事契合度、进一步游玩意愿；
- 三套强制完整排序；
- 可选开放反馈。

有效答卷必须：测试 ID 匹配、目标玩家筛选通过、注意力检查通过、三套均完成、排序不重复、匿名参与者 ID 不重复。页面不上传数据；每位参与者下载一个 JSON，由创作者汇总到 `responses/`。

## 6. 确定性推荐

先淘汰没有通过五类工艺门槛或玩家可读性低于 75% 的候选。至少两个候选仍合格时：

- 排名第一得 2 个 Borda 点、第二得 1 点、第三得 0 点；
- 同时计算每对候选中谁被排在前面的比例；
- 报告第一选择数、Borda 点、三个评分中位数和可读性正确率。

只有同时满足以下条件，分析结果才为 `player_leader`：

1. 至少 8 份有效目标玩家答卷；
2. 领先候选对每个合格对手的两两偏好率均不低于 60%；
3. 领先候选视觉吸引力中位数不低于 5/7；
4. 若为第二轮，使用新的参与者群体。

否则结果为 `inconclusive`，并列出具体失败条件。不要做显著性、市场规模或销量推断。

## 7. 状态与失败路径

- `draft`：简报或证据仍在建立；
- `candidates_ready`：三套真实样板存在，但质量门槛未全部完成；
- `test_ready`：三套均通过门槛，可发放盲测；
- `tested_inconclusive`：已有真实测试，但未达到玩家支持阈值；
- `player_supported`：玩家领先者达到阈值且创作者接受；
- `creator_selected_unvalidated`：证据不足或第二轮仍不明确，创作者自行选择；
- `creator_override`：存在玩家领先者，但创作者明确选择另一套并记录理由。

首轮不明确时，依据门槛失败和开放反馈最多修订两个候选，再测试一次。不要自动混合前两名；视觉假设混合后必须被视为新版本。第二轮仍不明确就停止扩张，让创作者在真实不确定性下裁决。

## 8. Style contract

完成创作者裁决后，从选中候选确定性导出紧凑契约：

- 决策状态与候选 ID；
- 综合样板相对路径和 SHA-256；
- style anchor；
- 像素/采样、调色、形状、光线、镜头、UI、动作和负面规则；
- 环境、角色、UI、叙事帧等资产族例外；
- visual decision 与 player analysis 的相对路径和哈希。

契约保留 `player_supported`、`creator_selected_unvalidated` 或 `creator_override`，下游不能把三者视为同等证据。
